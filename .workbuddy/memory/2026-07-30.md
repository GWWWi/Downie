## 开发：Windows 版 Downie 风格视频下载器 (DownieWin)
- 技术栈：yt-dlp（解析/下载）+ ffmpeg（合并/转码）+ PySide6（GUI）。
- 位置：`E:\test\gitHub\Downie\`，包名 `downie4win`。
- 结构：`app.py`(启动) / `config.py`(JSON 设置) / `downloader.py`(yt-dlp 封装 + QThread 进度信号) / `browser_server.py`(本地 HTTP 127.0.0.1:7654 接收浏览器扩展发来的链接) / `ui/`(主窗口+添加对话框+设置+列表项) / `browser_extension/`(MV3 扩展)。

## 18:27 补充：修复打包后运行报 relative import 错误
- 用户反馈打包后运行 exe 报 `ImportError: attempted relative import with no known parent package`（`__main__.py` line 1）。
- 根因：`build.spec` 的 Analysis 入口是 `downie4win/__main__.py`，其首行 `from .app import main` 是相对导入；PyInstaller 把它当顶层脚本冻结后没有父包，故崩。
- 修复：把 Analysis 入口改成项目根 `main.py`（其 `from downie4win.app import main` 是绝对导入，适合做冻结入口），包内相对导入在 `downie4win` 作为真实包时正常解析。
- 验证（沙箱内无法跑完整 PyInstaller——其 assemble 阶段会 `os.remove` 临时文件，被沙箱 safe-delete 拦截「recycle-bin-unavailable」；真实 Windows 有回收站不受限）：用 importlib 把旧 `__main__.py` 当顶层模块执行，精确复现原错误；确认 `main.py` 无顶层相对导入且 `downie4win` 作为真实包可正常导入。修复正确。
- 附带：`bin/` 现已含 ffmpeg.exe（用户本机下载成功），重打后的 exe 会把它一并打包。
- 沙箱测试产生的残留：`_build_leftovers/`（含旧 build 目录）可安全删除；根目录 `build/`、`dist/` 会在用户本机重打时被 `--clean` 覆盖。
